## Preservation gaps and phase boundary

1. **Database empty ≠ frontend delete:** homepage/about/guideline/navigation copy is authoritative fallback until field-by-field parity is verified.
2. Bespoke editors still need Phase B conversion to shared affected-row checking and archive semantics; Phase A migrates the shared repository primitive only.
3. Public empty states are user-friendly but are not preservation fallbacks for recovered DB content. Phase B must snapshot/verify before changing queries or status filters.
4. Legacy URL/path columns and `public/lovable-assets` remain required while media FK coverage is incomplete.
5. Settings, social, FAQ, policy, attendance, behaviour, parent/student instructions lack end-to-end editor parity.
6. Cache invalidation is standardized only for shared CMS hooks; bespoke mutations invalidate local keys inconsistently.
